# 测验评分学习笔记

## 1. 这个模块解决什么问题

对单选、多选和判断题进行稳定、可验证的自动评分，并将错误沉淀为用户维度的错题记录。

## 2. 为什么这样设计

客观题规则确定，适合由后端精确评分。简答题存在表达差异，第一版只提供学习反馈，不计入客观题正确率，避免伪精确评分。

## 3. 请求经过哪些类

```text
QuizAttemptController
→ QuizAttemptService
→ QuestionRepository
→ ObjectiveQuestionScorer
→ QuizAnswerRepository
→ WrongQuestionService
→ QuizAttemptResultVO
```

整个测验提交应位于一个事务中，保证答题记录、得分和错题状态一致。

## 4. 使用的 Java 和 Spring 知识

- 策略模式
- Enum 题型

- DTO 校验
- BigDecimal 或整数得分策略
- 唯一约束
- Mockito

## 5. 核心评分规则

- 单选：唯一选项相等。
- 判断：布尔答案相等。
- 多选：用户答案集合与标准答案集合完全相等，顺序不影响结果。
- 简答：保存文本并返回三级学习反馈。

## 6. 常见错误

- 使用字符串顺序直接比较多选答案。
- 用户漏选时仍给部分正确。
- 重复提交造成错题次数被重复增加。
- 测验中途异常但已写入部分答案。
- 把标准答案直接返回到未提交的题目接口。
- 简答题反馈参与客观正确率。
