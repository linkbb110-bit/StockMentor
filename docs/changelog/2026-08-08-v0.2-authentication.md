## 实现内容

### 注册与登录

- 注册和登录先通过 `EmailNormalizer` 对邮箱 trim、转小写并执行最终格式/长度校验；昵称由共享 `NicknameNormalizer` 先 trim 再校验。
- 密码保持原值语义，不自动 trim；只以 BCrypt 哈希写入 `sys_user.password_hash`。
- 注册默认创建 `USER`、`ACTIVE` 用户，更新首次 `last_login_at` 成功后才签发 Token 并返回 HTTP 201。
- 登录成功更新 `last_login_at` 后返回 HTTP 200；错误密码与不存在邮箱都返回 HTTP 401、`AUTH_INVALID_CREDENTIALS` 和相同公共消息。
- 数据库唯一索引 `uk_sys_user_email` 是并发重复注册的最终保护，并映射为 HTTP 409。

### JWT 与 Spring Security

- JWT 使用 Spring Security OAuth2 JOSE、HS256 和 7200 秒默认有效期，只包含 `sub`、`iat`、`exp`、`jti`。
- `JWT_SECRET` 只能来自环境变量；缺失或不足 32 字节时启动失败，不自动生成密钥。
- `JwtAuthenticationFilter` 每次受保护请求按 Token 用户 ID 重查数据库状态和最新角色；禁用或逻辑删除用户的旧 Token 立即失效。
- Security 使用 `STATELESS`，关闭 Form Login 与 HTTP Basic，提供统一 JSON 401/403；CORS 仅接受 `CORS_ALLOWED_ORIGINS` 的显式白名单。

### 当前用户与前端行为

- `GET /api/v1/users/me` 返回 `id`、`email`、`nickname`、`role`、`createdAt`，不返回密码哈希、内部状态或 Entity。
- `PATCH /api/v1/users/me/nickname` 只按当前认证用户 ID 更新并返回最新资料，不能修改邮箱、角色或状态。
- 前端提供 `/login`、`/register`、`/dashboard`、`/profile`；认证占位首页不显示未实现的学习统计。
- Pinia 在启动时恢复并验证会话；`sessionStorage` 只保存 `stockmentor.accessToken` 和 `stockmentor.currentUser`。
- Axios 添加 Bearer Token；受保护请求 401 清理会话并只跳转一次，登录失败 401 不产生重定向循环；退出仅清理本地状态。

4. 该次 preflight 失败报告中的 `mysql84-unchanged` 和 `runtime-log-scan` FAIL 是前置变量未赋值、运行日志尚未生成的派生清理噪声，不是服务状态变化或 secret 泄漏；独立清理核验与随后成功运行均证实服务状态和资源清理正常。
